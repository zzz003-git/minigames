# 오리지널 미니게임 4종 — 구현 명세

기획서 `game_planning_doc_v2.pdf` (내부 개발 기획서 | GAME SPEC · ver 1.0 · 대외비)를
이 저장소로 구현한 문서입니다. 기획서 원본은 저장소에 포함되어 있지 않습니다.

| # | 게임 | `game_type` | 폴더 | 순위 기준 지표 |
|---|---|---|---|---|
| ① | 스탑워치 챌린지 | `STOPWATCH` | `stopwatch` | 목표 타임과의 오차 (작을수록 상위) |
| ② | 숫자야구 | `BASEBALL` | `baseball` | 성공까지의 시도 횟수 (적을수록 상위) |
| ③ | 타이핑 스피드 | `TYPING` | `typing` | WPM 또는 CPM × 정확도% |
| ④ | 숫자 기억력 | `MEMORY` | `memory` | 맞힌 자리 수 → 동일하면 소요 시간 |

**아케이드 13종(⑤~⑰)과 다른 점은 엔진입니다.** 아케이드는 `src/lib/arcade.js` 의 공통 런
엔진 위에 spec 하나만 얹는 구조지만, 이 4종은 각각 고유한 흐름(스탑워치의 START/STOP,
숫자야구의 턴제 판정, 타이핑의 원본 대조, 기억력의 레벨 진행)을 가져서 게임마다 독립된
서버 모듈로 구현되어 있습니다. 그래서 `ARCADE` 설정표에 들어가지 않고
`CLASSIC_GAME_TYPES` 로 따로 묶여 있습니다.

수치는 전부 `src/lib/config.js` 의 `STOPWATCH` · `BASEBALL` · `TYPING` · `MEMORY` 에 있습니다.

## 1. 게임별 상세

### ① 스탑워치 챌린지 `STOPWATCH`

목표 타임을 보고 START → STOP 으로 그 시간을 맞춥니다.

| 항목 | 값 | 근거 |
|---|---|---|
| 목표 타임 | 1.00~9.99초 · 0.01초 단위 = **900가지** | 기획서 3장 |
| 생성 주체 | 서버 — 도전마다 새로 생성 | 기획서 3장 |
| 기본 도전 기회 | 하루 5회 | 와이어프레임 화면① 5칸 |
| 광고 보상 | 기회 +1 (Rewarded, 하루 3회) | 기획서 11장 |
| 리그(bucket) | **목표 타임별** (`"3.47"`) | 기획서 3장 Target-specific |
| 순위 지표 | `rank_metric` = 오차 절대값(ms) | 작을수록 상위 |

```
IDLE → 목표 타임 생성 → READY → RUNNING → STOPPED → RESULT
```

같은 목표 타임 도전자끼리만 비교합니다 — 3.47초와 7.21초는 난이도가 다르므로 한 줄에
세우면 순위가 목표값 뽑기 운이 됩니다.

**시간 검증** (`checkElapsed`)

- START 탭 시각(`armed_ts`)이 있으면 그것을 기준으로 검증합니다. 없으면 세션 생성
  시각을 쓰되 허용치를 느슨하게 둡니다 (`ARMED_IDLE_MS` 2.5초 / `MAX_IDLE_MS` 20초).
- 신고한 경과 시간이 서버 관측 시간창을 `DRIFT_TOLERANCE_MS`(500ms) 넘게 벗어나면 이상치.
- 오차가 `IMPOSSIBLE_GAP_MS`(2ms) 미만이면 `GAP_IMPLAUSIBLE` 로 표시해 통계에서 제외합니다.
  사람이 물리적으로 내기 어려운 정확도입니다.

### ② 숫자야구 `BASEBALL`

0~9 중 중복 없는 3자리를 맞힙니다.

| 항목 | 값 | 근거 |
|---|---|---|
| 정답 | 0~9 중복 없는 3자리 · 서버 생성 후 **AES-256-GCM 암호화** 저장 | 기획서 5장 |
| 기본 시도 | 6회 | 기획서 5장 |
| 광고 보상 | 시도 +3회 (Rewarded, **1게임당** 3회 = 최대 +9회) | 기획서 5장 |
| 판정 | Strike = 숫자·자리 일치 / Ball = 숫자만 일치 / Out = 둘 다 0 | 기획서 5장 |
| 리그(bucket) | `solved` / `failed` | — |
| 순위 지표 | 성공 시 시도 횟수, 실패 시 999 | 적을수록 상위 |

판정을 서버가 하므로 기획서 엔드포인트 목록에 없는 **`POST /game/guess`** 를 추가했습니다.
클라이언트가 정답을 가지고 있으면 "정답 절대 노출 금지"(기획서 12장)를 지킬 수 없습니다.

시도 기록(`history`)은 정답이 아니므로 세션 `meta` 에 저장합니다 — 새로고침해도 복원됩니다.

### ③ 타이핑 스피드 `TYPING`

제시된 문장을 제한 시간 안에 입력합니다.

| 항목 | 값 | 근거 |
|---|---|---|
| 언어 | `ko` / `en` / `mix` | 기획서 7장 |
| 난이도 | `easy` / `normal` / `hard` | 기획서 7장 |
| 순위 지표 | 한국어·혼합 **CPM**, 영어 **WPM** | 기획서 7장 |
| 최종 점수 | `지표값 × 정확도%` | 기획서 7장 |
| 제한 시간 | 글자수 × 언어 계수(ko 900 / en 450 / mix 800 ms), 30~180초로 보정 | 구현 추가 |
| 기본 도전 기회 | 하루 5회 | — |
| 광고 보상 | 새 문장 +1 (Rewarded, 하루 5회) | 기획서 11장 |
| 리그(bucket) | `{lang}:{difficulty}` | — |

**정확도와 점수는 클라이언트 값을 믿지 않고 서버가 다시 계산합니다.** 제출된 입력
문자열과 DB 원본 문장을 자리별로 대조하므로(`scoreText`) 위조가 불가능합니다.
초과 입력분은 오탈자로 셉니다.

> 정확도는 기획서 정의대로 **원본 전체 글자 수** 기준이라, 문장을 끝까지 치지 못하면
> 그만큼 낮게 나옵니다. 결과 화면에서 오해가 없도록 `completion`(완성도)을 함께 내려줍니다.

비정상 속도(`MAX_PLAUSIBLE_WPM` 600 초과)는 기록을 이상치로 남긴 뒤 요청 자체를
`ABNORMAL_SPEED` 로 실패시킵니다 (기획서 12장).

### ④ 숫자 기억력 `MEMORY`

N자리 숫자를 정해진 시간 동안 보고 가린 뒤 입력합니다.

| 레벨 | 자릿수 | 노출 시간 | 힌트 |
|---|---|---|---|
| LV1~2 | 4~5 | 5초 | — |
| LV3~4 | 6~7 | 4초 | — |
| LV5~6 | 8~9 | 4초 | **1회** |
| LV7~8 | 10~11 | 3초 | — |
| LV9~10 | 12~13 | 3초 | — |

기획서 9장 레벨 설계표를 그대로 옮겼습니다. 입력 제한 시간은 60초입니다.

- **레벨 잠금** — 자기 최고 레벨 이하는 자유롭게 재도전하고, 그보다 높은 레벨은 광고로 얻은
  **레벨 도전권**이 필요합니다 (Rewarded, 하루 3회 · 기획서 11장).
- **힌트** — LV5~6 에서만 1회. 아직 비어 있는 자리 하나의 정답을 알려 줍니다
  (`POST /game/hint`, 기획서 엔드포인트 목록에 없어 추가).
- **리그(bucket)** — `LV{n}`. 순위 지표는 `(틀린 자리 수 × 1,000,000) + 소요 시간` 이라
  맞힌 자리가 우선이고 같으면 빠른 쪽이 상위입니다.
- 클리어하면 최고 레벨을 갱신하고, 실패하면 최고 레벨은 유지됩니다.

## 2. 공통 광고 연동 (기획서 11장)

| 게임 | 트리거 | 보상 | 유형 | 한도 |
|---|---|---|---|---|
| ① | `STOPWATCH_ATTEMPT` | 기회 +1 | Rewarded | 3회/일 |
| ① | `STOPWATCH_STATS` | 통계 열람 | Interstitial | 제한없음 |
| ② | `BASEBALL_ATTEMPT` | 기회 +3 | Rewarded | 3회/**게임** |
| ② | `BASEBALL_STATS` | 통계 열람 | Interstitial | 제한없음 |
| ③ | `TYPING_SENTENCE` | 새 문장 +1 | Rewarded | 5회/일 |
| ③ | `TYPING_RANK` | 순위 열람 | Interstitial | 제한없음 |
| ④ | `MEMORY_LEVEL` | 레벨 도전권 | Rewarded | 3회/일 |
| ④ | `MEMORY_RANK` | 랭킹 열람 | Interstitial | 제한없음 |

②만 한도 기준이 「하루」가 아니라 「게임당」이라 `AD_TRIGGERS` 에서 `perDay: null` 로 두고
세션의 `ad_views` 로 셉니다. 통계·랭킹 열람은 Interstitial 시청 후 30분간 열립니다
(`COMMON.AD_UNLOCK_WINDOW_MS`).

아케이드 13종은 게임마다 `_ATTEMPT` / `_BOOST` / `_STATS` 3종을 **자동 파생**하지만,
이 4종은 트리거 이름과 보상이 게임마다 달라 `AD_TRIGGERS` 에 손으로 적혀 있습니다.

## 4. 기획서와 다르게 구현한 부분

README 의 같은 이름 절과 동일한 내용입니다. 여기에는 근거를 더 적어 둡니다.

| 항목 | 기획서 | 구현 | 이유 |
|---|---|---|---|
| 스탑워치 측정 주체 | 서버 타임스탬프만 사용 | 클라이언트 측정 + 서버 검증 | 서버 시각으로 오차를 계산하면 네트워크 지연이 기록에 섞여 실력이 아니라 회선 품질을 재게 됩니다. 대신 서버 관측 시간창을 벗어나는 신고를 거부합니다 |
| 숫자야구 실패 화면 | 정답 공개와 「기회 +3 충전」을 동시 제시 | 기회 소진 시 정답을 감춘 채 「광고 충전」/「포기하고 정답 보기」 | 정답을 알려준 뒤 같은 정답에 3번 더 도전하는 것은 게임이 성립하지 않습니다. 기획서 화면④의 모순입니다 |
| 목표 타임 노출 | "클라이언트에 결과만 전달 — 사전 노출 없음" | 목표 타임은 응답에 포함 | 목표를 모르면 플레이가 불가능합니다(와이어프레임 화면①에도 표시). 보호 대상인 **생성 규칙과 다음 목표값**은 노출하지 않습니다 |
| 난수 생성 | `Math.random` 기반 | `crypto.getRandomValues` | 예측 가능한 난수는 어뷰징 경로가 됩니다 |
| 일일 한도 기준 시각 | 명시 없음 | **KST(UTC+9) 자정** 리셋 | UTC 자정을 쓰면 한국에서 오전 9시에 리셋됩니다 |

## 5. 어뷰징 방지 (기획서 12장)

### 서버가 실제로 막는 것

- **시간 조작** — 시작/종료는 서버 타임스탬프 기준. 클라이언트 신고값이 서버 관측
  시간창을 벗어나면 거부하거나 이상치(`suspect`)로 표시해 통계에서 제외합니다.
- **정답 노출** — 숫자야구 정답과 타이핑 원본 문장 id 는 세션에 AES-256-GCM 으로
  암호화 저장되며 응답에 실리지 않습니다. 판정은 전부 서버가 합니다.
- **결과 위조** — 타이핑 정확도·점수는 서버가 원본과 재대조해 다시 계산합니다.
  클라이언트가 보낸 `wpm`·`accuracy` 는 쓰지 않습니다.
- **중복 제출** — `results.session_id` UNIQUE + 세션 상태(`OPEN`/`CLOSED`) 확인.
- **광고 한도** — 동일 IP 일일 광고 20회(`IP_AD_VIEWS_PER_DAY`), 게임별 한도는 위 §2.
- **비정상 속도** — 600 WPM 초과 자동 차단.

### 남아 있는 한계 (정직한 기록)

- **숫자 기억력은 정답을 화면에 반드시 보여줘야 합니다.** 개발자도구로 그 값을 읽는 것은
  원리적으로 막을 수 없습니다. 완전히 막으려면 숫자를 서버에서 이미지로 렌더링해야 합니다.
  다만 **채점은 서버가 원본과 비교**하므로 입력 결과를 위조하는 것은 불가능합니다.
- **타이핑 자동 입력**은 속도 상한(600 WPM)으로만 걸러집니다. 사람 속도 범위 안에서
  일정하게 치는 스크립트는 구분하지 못합니다.
- **광고 보상 검증**은 `AD_MODE=mock` 상태입니다. 실연동 전에 `live` 로 바꾸면
  `src/lib/adverify.js` 가 `501` 로 실패합니다 — 미구현 상태로 실서비스에 나가
  보상이 무료 지급되는 것을 막는 안전장치입니다.

## 7. 이번 작업에 포함하지 않은 것

- **개발 로드맵 Phase 3** (기획서 13장) — Android/iOS SDK 패키징, 매체사 파일럿 연동,
  보안 감사. 이 저장소는 WebView 로 감쌀 웹 구현까지입니다.
- **실제 광고 SDK 연동** — Rewarded/Interstitial 은 모바일 앱 SDK 기능이라 순수 웹에서
  그대로 재현되지 않습니다. 네이티브 브리지 자리만 `public/shared/ad.js` 에 열어 두었습니다.
- **쿠팡파트너스 등 매체사 API** — 기획서 Phase 1 항목이나 스펙 대기 상태입니다.
