# 디자인 v3 적용 — 버전 관리

전체 외형이 바뀌는 작업이라 **되돌릴 수 있는 상태로** 진행한다.
기능은 이미 완결돼 있고 바뀌는 것은 화면뿐이므로, 잘못되면 화면만 되돌리면 된다.

| | |
| --- | --- |
| 원안 | `오늘의나-스위트-v3.dc.html` (claude.ai/design 에서 받음 · 96KB) |
| 브랜치 | **`design/suite-v3`** — main 에서 갈라져 나왔다 |
| 기준 태그 | **`design-v3-base`** — 적용 **직전** 상태 |
| 프로덕션 | **영향 없음** — main 에 push 하지 않는 한 실서비스는 그대로다 |

---

## 왜 브랜치인가

프로덕션은 **`main` push 로 자동 배포**된다(CLAUDE.md 「배포 — 두 갈래」).
디자인 작업을 main 에서 하면 중간 상태가 실서비스로 나갈 위험이 상시로 있다.
브랜치에 두면 그 경로가 원천적으로 닫힌다.

**스테이징은 브랜치와 무관하게 작업 트리를 올린다.** 그래서 브랜치에 있어도
테스터에게 보여 주는 데는 아무 문제가 없다 — 오히려 이 조합이 목적에 정확히 맞는다.

```
design/suite-v3  →  wrangler deploy --env staging  →  테스터 확인
                 →  (승인)  →  main 병합  →  push  →  프로덕션
```

## 되돌리는 방법

```bash
# 무엇이 바뀌었는지 전체를 한눈에
git diff design-v3-base

# 화면만 통째로 되돌리기 (서버 로직은 그대로 둔다)
git checkout design-v3-base -- public/

# 브랜치를 통째로 버리기
git checkout main && git branch -D design/suite-v3
```

스테이징을 되돌리려면 **직전 버전 ID 로 롤백**한다. 배포할 때마다 아래 표에 적는다.

## 적용 범위 — 단계로 나눈다

원안은 **제품 전체**를 다시 정의한다(상단 통합 내비 · 1120px 폭 · 영역 카드 ·
게임 30종 목록 · 스위트 3종 · 도감). 한 번에 갈아엎지 않고 단계로 나눈다 —
중간에 멈춰도 화면이 깨지지 않는 단위여야 한다.

| 단계 | 내용 | 상태 |
| --- | --- | --- |
| **D-1** | 공용 상단 내비(전체 / 게임 / 오늘의 나 / 웹툰 준비중) + 「전체」 화면 | **적용** |
| **D-2** | 게임 영역 — 영역 카드 · 오리지널/아케이드 묶음 재구성 | **적용** |
| **D-3** | 오늘의 나 영역 — 3칸 카드·트리플 진행도 재구성 | **적용** |
| **D-4** | 서비스 3종 화면(타로·기운·마음) 팔레트 정렬 | **적용** |
| **D-5** | 게임 30종 화면 — 공용 골격만 손보고 개별 연출은 유지 | **적용** |

### D-1 에서 한 번 틀렸던 것

처음에 탭을 **둘(게임·오늘의 나)로만** 만들었다. 원안의 `tabDefs` 는 **넷**이고
첫 탭이 **「전체」**다.

```js
const tabDefs = [
  { label:'전체', view:'home' },
  { label:'게임', view:'games' },
  { label:'오늘의 나', view:'hub' },
  { label:'웹툰 준비중', view:null }   // onClick 을 빈 함수로 막아 뒀다
];
showGames: isHome || isGames,   // ← 전체 화면에서는 게임이 보이고
showHub:   isHome || isHub,     // ← 오늘의 나도 함께 보인다
```

두 영역을 **오가게만** 하면 「한 제품」이 아니라 「두 제품 사이의 스위치」가 된다.
전체 화면이 있어야 둘이 한 제품으로 보인다 — 그것이 원안의 중심이었다.

그래서 `/` 는 전체(게임 + 오늘의 나), `/games/` 는 게임만으로 갈랐다.
**게임이 위, 오늘의 나가 아래다** — 주 콘텐츠가 게임이고 오늘의 나는 하루 한 번
들르는 곳이라, 매번 여는 화면에서 먼저 보여야 하는 쪽은 게임이다.
오늘의 나 요약은 `/today/` 와 **같은 API 를 읽는다**(허브를 두 벌 만들지 않는다).

**D-1 이 먼저인 이유**: 두 영역이 서로를 모르면 한 제품이 아니다. 지금까지 미니게임
허브와 스위트 허브는 각자 있었고 오갈 방법이 링크 하나뿐이었다. 원안의 중심 아이디어가
그것을 상단 탭으로 바꾸는 것이라, 나머지 단계가 전부 이 위에 얹힌다.

## 원안을 그대로 옮기지 않은 곳

원안은 `.dc.html` 이라 **디자인 런타임(`support.js`)이 렌더링하는 목업**이다.
실제 화면은 기존 공용 모듈(`base.css` · `ui.js`)을 쓰므로, 값(색·간격·모양)은
가져오되 마크업 구조는 이쪽 골격에 맞춘다.

- **내비는 두 허브에만 단다.** 게임 화면·서비스 화면은 이미 뒤로가기가 있는 한 판
  안이고, 거기까지 탭을 달면 판을 도중에 벗어나게 만든다
- 인라인 스타일은 클래스로 옮긴다 — 30종이 같은 값을 공유해야 한다

## 원안에 있는데 아직 못 넣은 것

외형 단계에서 넣을 수 없는 것들이다. **데이터나 화면이 없어서**지 디자인을 뺀 것이
아니다. 근거가 생기면 그때 원안 그대로 넣는다.

| 원안 요소 | 막힌 것 | 풀리는 조건 |
| --- | --- | --- |
| 카드 순위(`c.rank`) · 「어제 상위 8종」 | 플레이 집계를 허브로 내리는 경로가 없다 | 집계 API |
| 「오늘의 나 한 장」 교차 리딩 | 220문장 DB(`cross_db_v1.json`)가 없다 | Master 미결 (S-3) |
| 아카이브 달력 | 월 단위 조회 API 가 없다 (`daily_agg` 에 데이터는 쌓이는 중) | API 하나 |
| 「우리 · 너를 맞혀볼게」 | 발급 화면이 없다 (서버·수신자 화면은 있다) | 페어 발급 화면 |

없는 것을 있는 척 적지 않는 것이 기준이다. 순서 근거가 없는데 「인기」라고 쓰면
그건 디자인이 아니라 만들어 낸 정보다.

## D-5 — 바꿀 것이 거의 없었다

**원안에 게임 「한 판」 화면이 없다.** `data-screen-label` 은 일곱뿐이고
(게임 영역 · 오늘의 나 허브 · 타로 · 기운 · 마음 · 우리 페어 · 준비중 영역)
그중 게임은 **목록 영역**이다. 맞출 대상 자체가 없다.

그리고 대조해 보니 원안의 공통값이 이미 `base.css` 토큰과 일치한다.

| 원안 | base.css |
| --- | --- |
| 카드 `#161d2b` | `--surface-2` |
| 테두리 `rgba(255,255,255,.06)` | `--border` |
| radius 24 / 20 / 16 / 999 | `--r-card` / `--r-btn2` / `--r-row` / `--r-pill` |
| 금 `#d6b166` · 민트 `#7fd8c0` | `--gold` · `--mint` |
| 밝은 문자 `#c6d0e0` | `--text-2` |

같은 시안 계보라 당연한 결과다. 그래서 팔레트는 손대지 않았다.

### 실제로 어긋나 있던 것 — 뒤로가기

`renderHeader` 의 뒤로가기가 **항상 `/`** 였고 라벨이 「게임 목록으로 돌아가기」였다.
D-1 에서 `/` 가 「전체」가 되면서 **말과 동작이 어긋났다** — 게임에서 나오면 게임
목록이 아니라 전체 화면에 떨어진다.

`back` 옵션을 두고 기본을 `/games/` 로 했다. 이 함수를 쓰는 화면의 대부분이 게임
30종이라 기본값만 바꾸면 30종이 한꺼번에 따라온다. 스위트 화면은 `/today/`,
허브는 `/` 를 넘긴다. **게임 30종 파일은 한 줄도 고치지 않았다** — 「공용 골격만
손보고 개별 연출은 유지」가 이런 뜻이다.

## D-4 에서 고른 것 — 배경으로 가른다

원안은 세 화면을 **강조색이 아니라 배경 색조**로 가른다.

| | 배경 radial | 원안 강조 | 이 저장소의 강조 |
| --- | --- | --- | --- |
| 타로 | `#241c3d → #171226 → #120f1e` (보라) | 금 `#d6b166` | 금 `#e8c46a` |
| 기운 | `#1d1b26 → #161520 → #111119` (중성) | 금 `#d6b166` | **파랑 `#9ab6f0`** |
| 마음 | `#16212b → #151a24 → #11141c` (청록) | 민트 `#7fd8c0` | 민트 |

**기운의 강조만 원안과 다르게 뒀다.** 원안대로 금색을 쓰면 타로와 같은 색이 되어
허브 3칸에서 두 서비스가 안 갈린다(원안 허브 카드의 서비스별 색은 데이터
바인딩이라 `.dc.html` 에 값이 없어서 확인할 수 없었다). 게다가 이 화면에는 그날의
오행 5색이 들어와서 고정 강조를 금색으로 두면 그것과 다툰다.

원안이 세 화면을 가르는 주 장치인 **배경은 그대로 옮겼으므로** 의도는 유지된다.

### 서비스 화면에는 내비를 단다

D-1 에서 「내비는 두 허브에만」이라고 적었는데, 서비스 화면은 예외다. 원안이
`activeView = inSuite ? 'hub' : v` 로 **스위트 안에서도 「오늘의 나」 탭이 켜진 채
남도록** 다루고 있다. 게임 화면은 판이 진행 중이라 탭을 달면 판을 벗어나게 되지만,
서비스 화면은 하루 몫을 마치고 **결과를 보는 자리**라 성질이 다르다.

## D-3 에서 합친 것

「전체」 화면의 요약과 허브가 **같은 것을 그리고 있었다.** 원안을 옮기고 나서야
드러났다 — 원안의 허브 영역과 전체 화면의 오늘의 나 영역이 같은 블록이다.

그래서 `shared/todaysection.js` 한 벌로 합쳤다. 허브(`/today/`)는 그것을 붙이고
포인트 두 칸만 더한다. `hub-index.js` 도 `shared/` 로 옮겼다(양쪽이 쓴다).
