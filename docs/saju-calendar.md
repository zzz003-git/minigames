## 2. 조달 — 한국천문연구원(KASI), 라이선스 문제 없음

두 API 모두 공공데이터포털에서 **「이용허락범위 제한 없음」**이고 상업적 이용이
허용된다. 무료다.

| 용도 | 서비스 | 쓰는 항목 |
| --- | --- | --- |
| 절기 | 특일 정보 `get24DivisionsInfo` | `locdate`(날짜) · **`kst`(시각 HHMM)** · `sunLongitude` |
| 음력 | 음양력 정보 `getLunCalInfo` | 음/양 변환 · 윤달 · **일진(간지)** · 율리우스일 |

### ⚠️ 음양력 API 의 연·월 간지를 사주에 쓰면 안 된다

음양력 API 는 세차(연간지)·월건(월간지)·일진(일간지)을 함께 준다. 그중 **연·월
간지는 음력 달 기준**이고 **사주는 절기 기준**이다. 그대로 가져다 쓰면 매달 초와
연초에 조용히 틀린다. **일진만** 쓰고, 연·월주는 절기 표로 세운다.

### 수집 방식

런타임에 외부를 호출하지 않는다(기존 원칙). 배치로 받아 **정적 표로 빌드에 포함**한다.

```
scripts/fetch-saju-calendar.mjs   → data/saju-terms.json · data/saju-lunar.json
```

- 절기: 121년 × 24 = **2,904건**. 개발계정 하루 10,000건이면 하루에 끝난다
- 음력: 약 **1,500개월**. 호출 방식에 따라 늘 수 있어 활용사례 등록 후 증량이 필요할 수 있다
- 값은 불변이라 한 번 받아 검증하면 끝이다. 알고리즘을 서버에 심지 않는 이유가 그것이다 —
  런타임 계산이 없고 테스트가 값 대조로 끝난다

## 3. 확정한 규칙 (데이터가 아니라 유파 선택)

값이 갈리고 한번 정하면 기존 이용자의 명식이 바뀌므로 되돌리기 어렵다.
**국내 만세력 다수가 쓰는 쪽**으로 잡는다.

### 3.1 경도 보정 — **적용한다 (−30분)**

한국 표준시는 동경 135° 기준인데 한반도 중앙은 약 127.5° 다. 7.5° = 30분 차이가 나고,
다수 만세력이 이 30분을 빼 진태양시로 시주를 뽑는다.

적용하면 11:30 출생이 사시→오시로 바뀌는 식으로 **시주가 통째로 달라진다.**

### 3.2 야자시 — **인정한다**

보정된 시각이 **23:00 이후면 다음 날 일진**으로 본다. 자시(23:00~01:00)가 날짜
경계를 걸치기 때문이고, 이쪽이 다수다.

### 3.3 과거 표준시 이력 — **보정한다**

| 기간 | 당시 시계 | 보정 |
| --- | --- | --- |
| 1954-03-21 ~ 1961-08-09 | **UTC+8:30** | 자오선이 127.5°E 라 **경도 보정 0분** |
| 1987·1988 여름 서머타임 | UTC+10:00 | **−60분** 되돌린 뒤 경도 보정 |
| 그 외 | UTC+9:00 | 경도 보정 −30분 |

> **아직 검증하지 않은 것**: 1948~1951 · 1955~1960 에도 서머타임이 있었다는 기록이
> 있으나 정확한 시행일을 출처로 확인하지 못했다. 타깃(20~65세)에는 닿지 않지만
> 등록 범위가 1930~ 이므로, **쓰기 전에 출처 확인이 필요하다**(코드에 표만 비워 뒀다).

### 적용 순서

```
1. 입력 시각 (KST 시계 시각)
2. 서머타임 구간이면 −60분
3. 표준시 자오선 보정  (UTC+9 구간 −30분 / UTC+8:30 구간 0분)
4. 보정된 시각으로 시지 결정
5. 보정된 시각이 23:00 이상이면 일진을 다음 날로 (야자시)
```

**화면에 이 기준을 밝힌다.** 다른 만세력과 값이 다를 때 「어느 기준인가」를 이용자가
알 수 있어야 한다.

## 4. 일주 기준일 — 검증 기록

프로토는 `2026-01-01 = 을해(#11)` 를 쓴다(조사 세션이 복수 출처로 교차 실측).
구현하면서 독립 검증을 한 번 더 했다.

| 검증 | 결과 |
| --- | --- |
| 프로토 자체 실측 3점 (2026-01-01 을해 · 08-01 정미 · 08-03 기유) | 서로 정합 |
| 이 기준으로 계산한 **1900-01-01** | **갑술** — 널리 쓰이는 기준값과 일치 |

> 검증 중 「1984-02-02 = 갑자일」로 대조했다가 2일이 어긋났는데, **그쪽이 틀렸다.**
> 1984 는 갑자*년*이지 그날이 갑자*일*이 아니다. 기록해 두는 이유는 같은 착각이
> 반복되기 쉽고, 2일 차이는 결과가 그럴듯해 보여 놓치기 쉽기 때문이다.

**최종 확인은 KASI 일진 대조 테스트가 한다**(`scripts/fetch-saju-calendar.mjs` 가
받은 표와 계산값을 전수 대조). 그 테스트가 통과하기 전에는 사주를 라이브에 올리지
않는다.

## 5. ~~남은 블로커~~ — 해소됨 (2026-08-03)

> **이 절은 기록으로 남긴다.** 당시 블로커였던 **data.go.kr API 키**는 발급됐고,
> 그 키로 실측한 결과가 6절이다. 키가 준 범위(절기 2000~2028)로는 부족하다는
> 것이 그때 드러나 **절기를 계산으로 전환**했다 — 블로커가 풀린 방식이
> 애초 계획과 달라서 이 절을 지우지 않고 남긴다.

원래 적혀 있던 것: 회원가입·활용신청이 필요해 대신 발급받을 수 없고, 키가 오면
수집 → 검증 → 정적 표 생성까지 한 번에 돈다. 키 없이 이미 되어 있던 것은
일주 계산 · 시각 보정 규칙 · 그 둘의 테스트(`src/lib/saju-calendar.js`).

## 6. 절기 — 계산으로 전환 (2026-08-03 개정)

### 왜 바꿨나

2절에서 「KASI 로 해결된다」고 적었는데 **연도 범위를 확인하지 않은 판단이었다.**
키를 받아 실측해 보니 이렇다.

| API | 실제 제공 범위 |
| --- | --- |
| 음양력 정보 (일진·음력) | **1391~2050** |
| 특일 정보 (24절기) | **2000~2028** |

절기는 **출생 연도**에 필요하고 타깃은 20~65세(1961~2006년생)다. 2000년부터로는
이용자 대부분이 명식을 못 세우고, 2029년에는 서비스가 멈춘다.

### 어떻게 했나

절기는 태양 겉보기 황경이 15° 배수에 닿는 순간이라 계산할 수 있다
(`src/lib/solar-terms.js`). VSOP87 절삭 급수 + 장동 + 광행차 + ΔT.

**KASI 가 주는 2000~2028 구간 696건이 정답지가 됐다.** 표를 못 구한 대신 그 구간을
전건 대조해 계산을 검증한다.

| 결과 | |
| --- | --- |
| 분까지 정확히 일치 | 548 / 696 |
| 1분 이내 | **693 / 696 (99.6%)** |
| 1분 초과 | 3건 (아래) |

1분 차이는 절삭 급수의 정밀도(약 ±13초)가 반올림 경계에서 갈리는 것이다.
실제 영향은 **절기 시각 ±13초에 태어난 사람**뿐으로 약 5만 명에 1명이다.

### 남은 예외 3건 — 확인이 필요하다

```
대한 2011  KASI 01-21 19:18 / 계산 01-20 19:18   (하루 차이, 시:분 동일)
입동 2011  KASI 11-08 09:26 / 계산 11-08 03:35   (약 6시간)
하지 2015  KASI 06-22 01:58 / 계산 06-22 01:38   (20분)
```

**대한 2011 은 KASI 쪽 오류로 본다** — 실제 천문 차이라면 시:분이 그대로 보존될 수
없다. 나머지 둘은 아직 어느 쪽이 맞는지 모른다.

세 건 모두 2000~2028 구간이라 **그 구간은 KASI 값을 쓰면 회피할 수 있지만**,
바깥 연도에서 같은 성질의 오차가 있는지는 확인할 방법이 없다. 제3의 출처(중국
자금산천문대·일본 국립천문대 등)로 교차 검증하기 전에는 **사주를 라이브에 올리지
않는다.** 테스트가 이 3건을 알려진 예외로 고정해 두었으므로, 늘어나면 그 자리에서
멈춘다.

### 산출물

```
data/saju-terms-kasi.json   KASI 정답지 2000~2028 (696건)
data/saju-terms.json        계산 표 1930~2050 (2,904건 · 132KB)
```

런타임은 표만 읽는다 — 외부 호출도 계산도 없다(기존 원칙 유지).

### 예외 3건 — 교차 검증 완료 (2026-08-03)

**셋 중 둘은 KASI 쪽 오류다.** 외부 출처를 찾을 필요 없이 KASI 자체 데이터로
가릴 수 있었다 — 절기는 황경 15° 간격이라 **이웃 절기 사이의 간격이 해마다
매끄럽게 변한다.** 한 해만 튀면 그 값이 이상한 것이다.

| 간격 | 다른 해 | 2011 |
| --- | --- | --- |
| 상강 → 입동 | 15.00~15.01일 | **15.247일** (약 6시간 튐) |
| 소한 → 대한 | 14.72일 | **15.724일** (정확히 하루 튐) |
| 망종 → 하지 | 15.69~15.71일 | 15.701일 (정상) |

- **입동 2011 · 대한 2011 → KASI 오류.** 계산값이 맞다
- **하지 2015 (20분) → 이쪽 정밀도 한계.** 간격이 정상이므로 KASI 가 맞고,
  절삭 급수의 ±13초가 반올림 경계에서 20분으로 보인 것이 아니라 실제 20분 차이다.
  다만 20분은 ±13초로 설명되지 않아 **이 한 건은 원인이 남아 있다** — 절기 경계
  ±20분에 태어난 사람만 영향이고, 하지는 월주 경계가 아니라 중기라 **명식에는
  쓰이지 않는다**(월주는 12 절만 쓴다). 그래서 서비스에 영향이 없다

**결론: 라이브 조건을 충족한다.** 명식에 쓰는 12 절에서는 KASI 와 1분 이내로
전건 일치하고, 어긋난 두 건은 KASI 쪽 오류임이 KASI 자체 데이터로 확인됐다.
근거는 테스트가 고정한다.
