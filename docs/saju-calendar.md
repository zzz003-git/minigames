## 2. 조달 — 한국천문연구원(KASI), 라이선스 문제 없음

두 API 모두 공공데이터포털에서 **「이용허락범위 제한 없음」**이고 상업적 이용이
허용된다. 무료다.

| 용도 | 서비스 | 쓰는 항목 |
| --- | --- | --- |
| 절기 | 특일 정보 `get24DivisionsInfo` | `locdate`(날짜) · **`kst`(시각 HHMM)** · `sunLongitude` |
| 음력 | 음양력 정보 `getLunCalInfo` | 음/양 변환 · 윤달 · **일진(간지)** · 율리우스일 |

### ⚠️ 음양력 API 의 연·월 간지를 사주에 쓰면 안 된다

음양력 API 는 세차(연간지)·월건(월간지)·일진(일간지)을 함께 준다. 그중 **연·월
간지는 음력 달 기준**이고 **사주는 절기 기준**이다. 그대로 가져다 쓰면 매달 초와
연초에 조용히 틀린다. **일진만** 쓰고, 연·월주는 절기 표로 세운다.

### 수집 방식

런타임에 외부를 호출하지 않는다(기존 원칙). 배치로 받아 **정적 표로 빌드에 포함**한다.

```
scripts/fetch-saju-calendar.mjs   → data/saju-terms.json · data/saju-lunar.json
```

- 절기: 121년 × 24 = **2,904건**. 개발계정 하루 10,000건이면 하루에 끝난다
- 음력: 약 **1,500개월**. 호출 방식에 따라 늘 수 있어 활용사례 등록 후 증량이 필요할 수 있다
- 값은 불변이라 한 번 받아 검증하면 끝이다. 알고리즘을 서버에 심지 않는 이유가 그것이다 —
  런타임 계산이 없고 테스트가 값 대조로 끝난다

## 3. 확정한 규칙 (데이터가 아니라 유파 선택)

값이 갈리고 한번 정하면 기존 이용자의 명식이 바뀌므로 되돌리기 어렵다.
**국내 만세력 다수가 쓰는 쪽**으로 잡는다.

### 3.1 경도 보정 — **적용한다 (−30분)**

한국 표준시는 동경 135° 기준인데 한반도 중앙은 약 127.5° 다. 7.5° = 30분 차이가 나고,
다수 만세력이 이 30분을 빼 진태양시로 시주를 뽑는다.

적용하면 11:30 출생이 사시→오시로 바뀌는 식으로 **시주가 통째로 달라진다.**

### 3.2 야자시 — **인정한다**

보정된 시각이 **23:00 이후면 다음 날 일진**으로 본다. 자시(23:00~01:00)가 날짜
경계를 걸치기 때문이고, 이쪽이 다수다.

### 3.3 과거 표준시 이력 — **보정한다**

| 기간 | 당시 시계 | 보정 |
| --- | --- | --- |
| 1954-03-21 ~ 1961-08-09 | **UTC+8:30** | 자오선이 127.5°E 라 **경도 보정 0분** |
| 1987·1988 여름 서머타임 | UTC+10:00 | **−60분** 되돌린 뒤 경도 보정 |
| 그 외 | UTC+9:00 | 경도 보정 −30분 |

> **아직 검증하지 않은 것**: 1948~1951 · 1955~1960 에도 서머타임이 있었다는 기록이
> 있으나 정확한 시행일을 출처로 확인하지 못했다. 타깃(20~65세)에는 닿지 않지만
> 등록 범위가 1930~ 이므로, **쓰기 전에 출처 확인이 필요하다**(코드에 표만 비워 뒀다).

### 적용 순서

```
1. 입력 시각 (KST 시계 시각)
2. 서머타임 구간이면 −60분
3. 표준시 자오선 보정  (UTC+9 구간 −30분 / UTC+8:30 구간 0분)
4. 보정된 시각으로 시지 결정
5. 보정된 시각이 23:00 이상이면 일진을 다음 날로 (야자시)
```

**화면에 이 기준을 밝힌다.** 다른 만세력과 값이 다를 때 「어느 기준인가」를 이용자가
알 수 있어야 한다.

## 4. 일주 기준일 — 검증 기록

프로토는 `2026-01-01 = 을해(#11)` 를 쓴다(조사 세션이 복수 출처로 교차 실측).
구현하면서 독립 검증을 한 번 더 했다.

| 검증 | 결과 |
| --- | --- |
| 프로토 자체 실측 3점 (2026-01-01 을해 · 08-01 정미 · 08-03 기유) | 서로 정합 |
| 이 기준으로 계산한 **1900-01-01** | **갑술** — 널리 쓰이는 기준값과 일치 |

> 검증 중 「1984-02-02 = 갑자일」로 대조했다가 2일이 어긋났는데, **그쪽이 틀렸다.**
> 1984 는 갑자*년*이지 그날이 갑자*일*이 아니다. 기록해 두는 이유는 같은 착각이
> 반복되기 쉽고, 2일 차이는 결과가 그럴듯해 보여 놓치기 쉽기 때문이다.

**최종 확인은 KASI 일진 대조 테스트가 한다**(`scripts/fetch-saju-calendar.mjs` 가
받은 표와 계산값을 전수 대조). 그 테스트가 통과하기 전에는 사주를 라이브에 올리지
않는다.
