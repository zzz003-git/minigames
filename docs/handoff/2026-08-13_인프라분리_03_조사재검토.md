## 3. 권고에 빈 곳 넷

### 3-1. 【가장 큼】 Q5 백업 — **덤프를 어디에 두는지가 없습니다**

`wrangler d1 export` 덤프에는 **고객 일기 암호문 · 민감정보 플래그 · 초대코드**가 통째로 들어갑니다. D1 안에서 암호화돼 있다는 것과, **덤프 파일이 안전하다는 것은 다른 이야기**입니다.

빠진 결정 넷:

1. **`minigames` 는 git 저장소입니다.** 덤프를 저장소 폴더에 만들면 실수 한 번에 고객 일기가 **git 히스토리에 영구히** 들어갑니다. 히스토리에서 지우는 것은 강제 push 를 동반하는 사고 처리입니다. → **`.gitignore` 에 덤프 경로를 먼저 넣고 시작해야 합니다.**
2. **보관처.** PC 로컬이면 그 PC 가 곧 개인정보 보관 장소가 됩니다 — 백업·분실·양도 시 처리가 따라옵니다.
3. **복호화 키와의 거리.** 키가 덤프와 같은 기계에 있으면 암호화의 방어력이 절반 줍니다.
4. **자동화.** 수동 일일 덤프는 반드시 잊힙니다. 잊힌 백업은 없는 백업입니다.

> **「일일 덤프를 남긴다」는 반나절 작업이 아니라 결정 사항입니다.** 위 넷을 정하기 전에는 착수하지 않는 편이 낫습니다. 정하고 나면 실행 자체는 정말 몇 초입니다.

### 3-2. Q2 견적에 **도메인**이 빠졌습니다

D1 반나절 · Worker 2~3일은 **인프라만** 본 견적입니다. 금융사 심사에서 **먼저 보이는 것은 도메인**이고, 개인정보처리방침도 통상 **서비스·도메인 단위**로 걸립니다.

지금은 `minigames.zzz00321.workers.dev` **한 주소에 게임과 개인 일기가 함께** 있습니다. **「별도 도메인 + 별도 처리방침」이 견적에 포함되어야** 법무가 판단할 재료가 갖춰집니다.

(조사 세션은 법률 판단을 하지 않습니다. **견적 항목이 빠졌다**는 지적입니다.)

### 3-3. Q4-2 수정안에 함정 — **전 흐름 시나리오는 스모크 테스트로 못 만듭니다**

`test-api.mjs` 에 너의스토리를 넣자는 방향은 맞습니다. 다만 —

* 이 테스트는 `BASE = http://127.0.0.1:8787` (로컬 `wrangler dev`) 대상입니다.
* 너의스토리 **전 흐름은 PC 워커 브리지(LLM 파이프라인)가 붙어야** 돕니다. 로컬 테스트 환경에는 워커가 없습니다.

→ **서버 쪽만 떼어 테스트해야 합니다.** 대상 후보:

| 검사 | 왜 |
| --- | --- |
| 접수 → `queued_brain` 전이 | 상태 기계 입구 |
| G1 반려 시 **티켓 무차감** | 과금 규칙 |
| `queued_image` 진입에서 **차감 1회** | **차감 지점이 하나**라는 설계의 핵심 |
| `ys_ledger` **consume/refund 쌍** | 실패 시 잔액 복구 |
| `ys_order_source` 암·복호 왕복 | 공용 `crypto.js` 회귀를 잡는 자리 |
| 삭제 시 원문만 파기 | 오늘 데이터로 확인된 동작의 회귀 방지 |

워커는 가짜(고정 응답)로 세웁니다. **착수 전에 이 범위를 정하지 않으면 중간에 막힙니다.**

### 3-4. Q6 권고에 한 줄 덧붙입니다

지금 `0021~0023` 을 스테이징에 적용하면 그것은 **사후 대조군**입니다 — 이미 프로덕션에 들어간 것과 같은 파일이라 「먼저 돌려 검증」이 아닙니다. 개발 세션도 그렇게 적으셨으니 이견은 아니고, **규칙이 실제로 작동하기 시작하는 것은 `0024` 부터**라는 것을 기록으로 남깁니다.

## 4. 우선순위 이견 하나 — **D1 분리가 4순위인 것이 아깝습니다**

개발 세션은 D1 분리를 「법무 답 이후」로 두셨는데, **법무 답과 무관하게 얻는 것이 큽니다.**

| 얻는 것 | 설명 |
| --- | --- |
| **Q5 가 같이 풀립니다** | DB 가 갈리면 **Time Travel 이 곧 서비스 단위 복구**가 됩니다. 「표 단위 복구가 없다」는 문제가 사라집니다 |
| **Q4 회귀 반경 축소** | 공용 자원 하나가 줄어듭니다 |
| **비용이 이미 산정돼 있습니다** | 개발 견적으로 **반나절 · 파일 3개 · 이관 31행** |

그리고 1-3 의 *"지금 트래픽이 사실상 0이라 분리의 이득이 비용보다 작다"* 는 **반만 맞다고 봅니다.**

> 트래픽 0 은 **장애의 영향**을 줄이는 것이지 **분리의 비용**을 늘리지 않습니다. 오히려 **지금이 가장 쌉니다** — 이관 31행, DB 0.75MB. 시간이 갈수록 공유 코드가 늘어 비싸지고, **오늘 `config.js` 를 두 번 고친 것이 그 증거**입니다.

「외부 공개 직전」이라는 시점은 **Worker 분리에는 타당**하지만, **D1 분리를 미룰 이유로는 약합니다.** 법무 답이 늦어지면 그만큼 계속 미뤄집니다.

**제안하는 순서**

| 순위 | 항목 | 바뀐 점 |
| --- | --- | --- |
| 1 | **Q6 — 스테이징 적용 + 선적용 규칙** | 개발 의견과 동일 |
| 2 | **Q5 백업 — 「어디에·누가·어떻게」 먼저 결정** | 실행이 아니라 **결정**이 2순위 (3-1) |
| 3 | **Q2 D1 분리** | **4 → 3.** 법무 답과 분리해 판단. Q5·Q4 가 함께 좋아집니다 |
| 4 | **Q4-2 ys 테스트** | 범위를 3-3 으로 좁혀 착수 |
| 5 | Q1 Worker 분리 | 외부 공개 직전 (동일) |
| 6 | Q3 cron·폴링 | 급하지 않음 (동일) |

**`touchUser()` 결정은 3순위 착수 시 함께 정해야 합니다** — 빼는가 / 양쪽에 쓰는가. 이것 하나가 D1 분리의 유일한 교차점입니다.

## 5. 답변 범위 밖이지만 Master 께 올릴 사실 하나

§7-3 에 지나가듯 적힌 문장입니다.

> *"오늘 파일럿 10회 중 8회가 실패했는데, 환불이 전부 원장에 남아 대조가 가능했습니다"*

**실패율 80% 입니다.** 원장 설계 덕에 환불이 대조된다는 것은 **실패를 잘 처리했다**는 뜻이지 **실패가 적다**는 뜻이 아닙니다.

인프라 질의의 답변 범위 밖인 것은 맞습니다. 다만 이 수치는 **파일럿 성패의 핵심 지표**이고 인프라 문서 각주로 지나갈 것이 아니라고 봅니다. **별도 보고를 청합니다** — 8회의 실패 사유 분포(G1 반려 / G2 콘티 실패 / 예산 중단 / 워커 정지)와, 그중 **구조 문제와 튜닝 문제의 구분**입니다.

* `git` 을 실행하지 않았습니다. **커밋은 개발 세션 몫**입니다.
* **법률·개인정보 심사 판단은 하지 않았습니다.** 3-2 는 「견적 항목이 빠졌다」는 지적입니다.

* 위 제안 중 **아무것도 실행하지 않았습니다.**
