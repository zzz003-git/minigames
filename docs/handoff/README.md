# docs/handoff — 세션 간 질의·회신 기록

> 신설 2026-08-13 (Master 지시). **미니게임 저장소 안에 질의와 회신을 짝으로 남기는 곳**입니다.

## 왜 여기인가

질의는 조사 세션이, 답변은 개발 세션이 씁니다. 그런데 2026-08-13 까지 **질의는 `reward-minigame-research/reports/` 에, 답변은 어느 저장소에도 없이 채팅에만** 있었습니다. 한쪽만 읽으면 무슨 결정이 왜 내려졌는지 되짚을 수 없습니다.

**미니게임 저장소를 여는 사람이 이 폴더만 보면 그동안의 논의를 전부 따라올 수 있어야 합니다.**

## 파일 이름 규칙

```
YYYY-MM-DD_<주제>_NN_<누가·무엇>.md
```

- `NN` 은 **주고받은 순서**입니다. 01 질의 → 02 답변 → 03 재검토 → 04 …
- 같은 주제의 후속 논의는 **날짜를 바꾸지 말고 번호만 잇습니다.** 한 주제가 한 묶음으로 남아야 합니다.
- 주제가 바뀌면 새 날짜·새 주제로 01 부터 시작합니다.

예시 (첫 묶음):

| 파일 | 쓴 곳 |
| --- | --- |
| `2026-08-13_인프라분리_01_조사질의.md` | 조사 세션 |
| `2026-08-13_인프라분리_02_개발답변.md` | 개발 세션 |
| `2026-08-13_인프라분리_03_조사재검토.md` | 조사 세션 |

## 누가 쓰는가

| | 권한 |
| --- | --- |
| 개발 세션 | 이 폴더에 자유롭게 쓰기 |
| 조사 세션 | **이 폴더에만 쓰기 예외** (2026-08-13 Master 승인). `minigames` 의 나머지는 **읽기만** — 코드·`docs/` 의 다른 파일·`scripts/`·`data/deployed_games.csv` 는 그대로 개발 세션 소유입니다 |
| 양쪽 공통 | **`git` 은 개발 세션만 실행합니다.** 조사 세션은 파일만 놓고 `HANDOFF.md` 에 한 줄 남깁니다 |

## 쓸 때 지키는 것

1. **실측과 추정을 섞지 않습니다.** 확인하지 못한 것은 「미확인」이라고 적습니다.
2. **상대의 주장을 검증했으면 검증 방법을 적습니다.** "확인했다" 만으로는 되짚을 수 없습니다.
3. **하지 않은 것을 명시합니다.** (예: "D1 은 읽기 전용 SELECT 만 했다", "법률 판단은 하지 않았다")
4. **결론과 미결을 나눕니다.** 미결은 누가 답할 차례인지 적습니다.

## 주의 — 이 폴더에 커밋하면 배포가 돕니다

`CLAUDE.md` 「배포 — 두 갈래」에 적힌 대로 **`main` push 는 문서만 바꾼 커밋이어도 Workers Builds 가 배포를 돌립니다.**

문서 하나에 프로덕션 배포 한 번이 붙는 것이 부담이면, **Workers Builds 의 빌드 감시 경로에서 `docs/` 를 제외**하면 됩니다(Cloudflare 대시보드 → Workers Builds → Build watch paths). 이 폴더에는 코드가 없으므로 제외해도 잃는 것이 없습니다.

**결정 전까지는 문서 커밋을 모아서 한 번에 하시길 권합니다.**

## 절대 넣지 않는 것

- **고객 데이터·D1 덤프.** `ys_order_source` 에는 고객이 쓴 글이 들어 있고, 여기는 **git 저장소**라 한 번 들어가면 히스토리에서 지워지지 않습니다.
- 시크릿·`.env`·키.
- 개인정보(이름·연락처·리뷰 작성자 정보).
