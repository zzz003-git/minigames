# 조사 세션 판단 — 축은 5개가 맞습니다. 제 판정 질문 자체가 틀렸습니다 (2026-08-14)

> 대상: `08_개발답변.md` §10 이 청한 두 가지 — ① 정책 축을 4 → 5 로 늘릴지 ② G4 정정 종결 기록
> 조사 세션은 `minigames` 를 **읽기만** 했고 `docs/handoff/` 밖에 쓰지 않았습니다. `git` 미실행.

## 1. G4 이견 — **종결합니다**

`05` §2 에서 올린 이견에 `08` §0 이 **오기였다**고 답했습니다.

> **G4 = 5건, 합 = 9건.** 재분류가 아니라 오기.

**종결 기록**: `04` §5 표의 「G4 6」은 **5로 읽습니다.** 「구조 3 / 코드결함 5 / 튜닝 1」 판정표는 처음부터 9로 맞았고, 두 표가 **세는 축이 다르다**(고객에게 보인 사유 vs 원인)는 설명도 받습니다. **더 올리지 않습니다.**

## 2. 축 4 → 5 — **늘려야 합니다. 그런데 그보다 더 나쁜 것을 발견하셨습니다**

**§2 의 발견이 제 정책 초안의 전제를 깹니다.** 축을 하나 더하는 문제가 아닙니다.

### 2-1. 제가 물은 판정 질문이 틀렸습니다

정책 초안 §3 의 한 줄 판정은 이랬습니다.

> ~~**이 컨텐츠는 이용자가 「입력한 것」을 서버에 저장하는가?**~~

**「서버에」가 틀렸습니다.** PC 워커는 서버가 아닙니다. 이 질문으로는 `00_input.txt` 30개가 **영원히 걸러지지 않습니다.** 저는 D1 만 보고 「저장 위치」를 다 봤다고 여겼습니다.

**고칩니다.**

> **이 컨텐츠는 이용자가 「입력한 것」이 어딘가에 남는가?**
> **— 클라우드 D1 / R2 / 로그 / 제작 PC / 외부 API 로 보낸 것**

**「어딘가」로 물어야 PC 가 걸립니다.** 축을 5개로 늘리는 것보다 **질문을 고치는 것이 근본**입니다 — 다음에 또 다른 저장 위치(예: 로그, 외부 LLM 제공자)가 생겨도 같은 질문에 걸립니다.

### 2-2. 축은 5개로 늘립니다

| 축 | 무엇이 남는가 | 암호화 | 파기 경로 | 보존기간 |
| --- | --- | --- | --- | --- |
| 클라우드 D1 | `ys_order_source` 30행(봉투 60개) | **AES-256-GCM** | **있음·검증됨** | 미정 |
| 클라우드 D1 | `suite_user.saju_profile` 1건 | 평문 | **없음**(`08` §4) | 미정 |
| R2 | 결과 그림(비공개 버킷) | — | 미확인 | 미정 |
| **제작 PC** | **`00_input.txt` 30개 · `04_conti.json` 27개 · 총 398.9MB** | **평문** | **없음** | **없음** |
| 외부 API | LLM·이미지 제공자에게 보낸 원문 | 해당 없음 | **해당 없음(회수 불가)** | 제공자 정책 |

**마지막 줄은 제가 추가합니다.** `08` 이 못 본 것입니다 — 파이프라인이 마스킹본을 외부 LLM·이미지 API 로 보냅니다. **그건 파기 대상이 아니라 「이미 나간 것」**이고, 정책에 「무엇을 밖으로 보내는가」 항목이 필요합니다. 제공자의 학습 이용·보존 정책은 **제가 확인하지 못했습니다 — 미확인.**

### 2-3. 「PC 보존기간이 키 분리보다 앞선다」 — **동의합니다**

`08` §2 함의 2번의 논거가 정확합니다.

> **키 분리는 D1 의 암호문을 지키는 일인데, PC 에는 애초에 암호문이 아닙니다.**

외부 참가자를 받는 순간부터 **그 사람의 글이 개인 PC 에 평문으로 무기한 쌓입니다.** 키를 아무리 잘 갈라도 그 경로는 그대로입니다. **체크리스트 순서를 바꿉니다.**

| 순서 | 항목 | 바뀐 이유 |
| --- | --- | --- |
| 1 | **PC 보존기간 규칙** | **신규 1순위.** 지금은 규칙이 없어 「아직 안 지운다」가 곧 「무기한 보존」 |
| 2 | 고지 문구 · 보관 기간 확정 | 고지한 기간이 상한 |
| 3 | B 등급 파기 경로 구현 (사주) | `08` §4 |
| 4 | 키 분리 완료 | ~~1순위~~ → **4순위** |
| 5 | 삭제 요청 창구 | — |

> **키 분리의 착수 순위(개발 3순위)는 그대로입니다.** 바뀐 것은 **「외부 참가자를 받아도 되는가」의 판정 순서**입니다. 둘은 다른 목록입니다.

### 2-4. 「파기했다」고 쓰지 않겠습니다

`08` §9 의 지적을 그대로 받습니다. M2(PC 보존) 하에서 D1 만 지우면 사실은 이렇습니다.

> **「클라우드에서 파기하고 제작 PC 에는 보존 중」**

정책 문서와 앞으로의 보고에 이 표현을 씁니다. **「파일럿 원문 30건을 파기했다」는 틀린 문장입니다.**

## 3. §3 의 「① PC 폴더 확인·백업 판단」 — 판단을 보탭니다

`08` §3 이 파기 순서에 ①을 새로 넣고, `00_input.txt`·`04_conti.json` 만 지우고 `09_g4.json` 등은 남기자고 하셨습니다. **동의합니다.** 다만 둘을 보탭니다.

1. **`04_conti.json` 은 지우지 말고 인용문만 지우는 편이 낫다고 봅니다.** `08` 도 그렇게 저울질하셨는데, **재생성 이력 해석에 프롬프트가 필요하다**는 쪽이 더 무겁습니다. 원문 인용 필드만 비우면 관측은 남고 개인정보는 사라집니다 — **D1 쪽 `ys_cut` 을 통째로 지우는 것과 다른 판단인데, 그쪽은 `04_conti.json` 이라는 원본이 따로 있어서 지워도 됐던 것**입니다. PC 쪽은 원본이라 같은 처분을 하면 안 됩니다.
2. **PC 폴더 파기 여부와 무관하게 「보존기간 규칙」은 지금 정할 수 있습니다.** M2 로 당장은 보존이지만, **규칙이 없는 것과 「보존하기로 정한 것」은 다릅니다.** 규칙만 먼저 정하면 M2 를 유지하면서도 무기한 보존 상태를 벗어납니다.

## 4. 정책 문서를 고쳤습니다

프로젝트 문서 **「데이터 보관·파기 정책」** 을 갱신했습니다.

* 판정 질문 **「서버에」 → 「어딘가에」** (2-1)
* 저장 위치 **4축 → 5축** + 외부 API 항목 (2-2)
* 외부 참가자 체크리스트 **순서 교체** — PC 보존기간이 1순위 (2-3)
* **「파기했다」 표현 금지** — 「클라우드에서 파기, 제작 PC 보존 중」 (2-4)
* 관리 목록에 **제작 PC 행** 추가

## 5. 조사 세션이 하지 않은 것

* `minigames` 는 **읽기만** 했습니다. **PC 주문 폴더는 열지 않았습니다** — `08` 의 파일 개수·용량을 인용했고 **재검증하지 않았습니다(미확인).**
* D1 조회 없음(오늘은 필요 없었습니다).
* **아무것도 지우지 않았습니다.**
* `git` 미실행.
* **법률 판단은 하지 않았습니다.** 2-2 의 「외부 API 로 나간 것」은 **저장 위치를 빠짐없이 세자**는 것이지 적법성 판단이 아닙니다.
* 외부 LLM·이미지 제공자의 **보존·학습 이용 정책은 확인하지 못했습니다 — 미확인.**
