## B. 지금 착수 가능 — 아무것도 기다리지 않습니다

### B1. Q6 — 스테이징에 `0021~0023` 적용 + 선적용 규칙 【1순위】

**막는 것 없음.** 스테이징 D1 에 `ys_` 테이블이 **0개**라(조사 세션 독립 확인) 너의스토리는 프로덕션이 첫 실행 환경이었습니다. `d1 migrations apply --remote` 는 되돌릴 수 없는데 **대조군이 아예 없습니다.**

* 지금 적용하면 **사후 대조군**입니다 — 이미 프로덕션에 들어간 것과 같은 파일이라 「먼저 돌려 검증」이 아닙니다.
* **규칙이 실제로 작동하기 시작하는 것은 `0024` 부터**입니다. 그래도 지금 해 둬야 다음이 됩니다.
* 스테이징에서 대기열까지 돌리려면 `wrangler.jsonc` staging 의 `"crons": []` 를 살려야 합니다.

### B2. Q4-2 — 서버 쪽 검사 7건 【2순위】

**막는 것 없음.** 공용 모듈 회귀가 지금 **한 방향에서만** 잡힙니다 — `test-api.mjs` 에 너의스토리 시나리오가 **0개**(조사 세션 grep 확인). 게임 때문에 `lib/` 를 고치면 너의스토리가 깨져도 아무도 못 잡습니다.

| # | 검사 | 잡는 것 |
| --- | --- | --- |
| 1 | 접수 → `queued_brain` | 상태 기계 입구 |
| 2 | G1 반려 시 티켓 무차감 | 과금 규칙 |
| 3 | `queued_image` 진입에서 차감 1회 | 차감 지점 단일성 |
| 4 | **`charge` 재호출 시 `consume` 1행 유지** | 멱등 (`ys-worker.js:275-290` 확인) |
| 5 | `ys_ledger` consume/refund 쌍 | 실패 시 잔액 복구 |
| 6 | **`ys_order_source` 암·복호 왕복** | **공용 `crypto.js` 회귀 — B3 키 분리의 안전망** |
| 7 | 삭제 시 원문만 파기 | 검증된 동작의 회귀 방지 |

**착수 전 함정 넷** (04 §3-2 + 조사 보탬)

1. **가짜 워커는 필요 없습니다** — `/ys/w/*` 는 `x-ys-worker` 헤더 하나로 인증하므로 테스트 스크립트가 직접 워커 역할을 합니다.
2. **`npm run db:migrate:local` 에 `0021~0023` 이 들어가야** 합니다. 로컬 D1 에 `ys_` 표가 없으면 전부 500 입니다.
3. **첫 줄에서 `/ys/w/ping`** 을 한 번 때려 heartbeat 를 세웁니다. 5분보다 낡으면 접수가 `service: "reserve"` 로 빠져 시나리오 전체가 어긋납니다.
4. **로컬 `SESSION_SECRET`(`.dev.vars`)이 있어야** 검사 6번이 돕니다.

> **6번을 1~5번보다 먼저 만드시길 권합니다.** B3 키 분리의 안전망이라 순서상 앞에 와야 합니다(04 §3-3 본문과 같은 판단).

### B3. 키 분리 (`YS_ENC_SECRET`) 【3순위 · A7 승인됨】

**착수 승인이 났습니다. 다만 D2 가 먼저입니다.**

```
D2 확정(ys_cut 평문 방침)  →  원문 30건 파기  →  키 분리  →  백업
```

**A3 덕분에 작업이 가벼워졌습니다.**

| | 원문을 남긴 채 | **먼저 파기하고** |
| --- | --- | --- |
| 재암호화 대상 | 봉투 **60개**(30행 × `raw_text`·`masked`) | **0개** |
| 읽기 겸용 코드 | 필요 → 나중에 제거 | **불필요** |
| `sha256` 대조 배치 | 필요 | 불필요 |

**「반나절 + 배치 + 겸용 코드 제거」가 「새 키로 새로 쓰기 시작」으로 줄어듭니다.**

**파기해도 파일럿 관측은 하나도 잃지 않습니다** — `ys_order` 31 · `ys_audit` **128** · `ys_ledger` 가 남습니다. 실패 분포·게이트 임계값·톤 오진율·원장 대조가 전부 그쪽에 있습니다.

**방법**: **기존 삭제 경로**(policy §3-4)를 씁니다. **수동 `DELETE` SQL 을 쓰지 않기를 권합니다** — 그 경로는 「원문만 파기, 운영 기록 보존」을 이미 구현하고 검증됐습니다(`YS-20260810-0001` 이 `deleted` 인데 `ys_order_source` 대응 행 없음 — 조사 세션이 `ys_order` 31 vs `ys_order_source` 30 으로 독립 확인). 수동 SQL 은 그 구분을 사람이 매번 다시 지켜야 합니다.

**되돌릴 수 없으므로**, 파일럿 분석에 원문이 더 필요하지 않은지 개발 세션이 먼저 확인해 주십시오(D5).

## G. 조사 세션이 하지 않은 것

* `minigames` 는 **읽기만** 했습니다. `docs/handoff/` 외 어떤 파일도 만들거나 고치지 않았습니다.
* D1 은 **읽기 전용 SELECT** 만 했습니다(`rows_written: 0`). **개인정보 값을 조회하지 않았습니다** — 행 수와 컬럼 이름만 봤습니다.
* **아무 데이터도 지우지 않았습니다.** B3 의 파기는 개발 세션이 D2·D5 확정 후 실행합니다.
* **`git` 미실행.** A8 로 커밋 승인이 났으나 **조사 세션은 git 을 실행하지 않는 것이 규칙**이라(2026-08-01 확정) 커밋은 개발 세션 몫입니다.
* **법률 판단은 하지 않았습니다.**
* 계정 플랜은 **미확인**입니다 — E 표의 백분율은 개발 세션의 무료 플랜 기준 인용이며 검증하지 않았습니다.
