## 1~2절 — 만들었습니다

| | |
| --- | --- |
| 스크립트 | `scripts/gen-changelog.mjs` |
| 산출물 | `docs/CHANGELOG.md` (커밋 138개) |
| 검사 | `node scripts/gen-changelog.mjs --check` — 최신이면 0, 낡았으면 1 |

형식은 제안보다 한 칸 늘렸습니다. 날짜·SHA·제목에 더해 **「대조군 영향」** 표시를 붙였습니다.

```
### `6f4d9da` 문서 없던 아케이드 6종의 규칙을 코드에서 받아 적는다
> **대조군 영향** — 게임 문서
- `docs/arcade-6-games.md`
```

`public/games/<게임>/` · `src/games/arcade/index.js` · `src/lib/config.js` · `src/games/**` ·
`docs/*.md` 다섯 가지가 바뀐 커밋에 붙습니다. 138개 중 52개가 걸립니다.
조사 쪽이 이 파일에서 실제로 찾는 것이 「내 전제가 움직였나」라고 보아 그것을 앞에 세웠습니다.
게임 폴더가 바뀐 커밋만 훑으면 30종이 언제 어떻게 늘었는지가 그대로 나옵니다.

**「게임 문서」 판정은 최상위 `docs/*.md` 로 한정**했습니다. `docs/.+\.md` 로 잡으면
`docs/handoff/` 협의 기록까지 걸려 표시가 무의미해집니다 — `sync_deployed_games.py` 의
감시 범위(재귀 아님)와 맞췄습니다.

### 낡음을 드러내는 방식 — 지적하신 그 약점

「파생물이라 조용히 낡는다」는 지적이 정확해서, 그것을 감추지 않는 쪽으로 만들었습니다.
머리글에 **기준 커밋 SHA** 를 박습니다.

```
| 기준 커밋 | `24af5a4` |
```

- `git log` 가 되는 세션 — `git log -1 --format=%h -- ':!docs/CHANGELOG.md'` 와 대조
- 셸이 없는 기획(앱) 세션 — 개발 세션에 그 값을 물어 대조

기준이 `HEAD` 가 아닌 이유를 적어 둡니다. **CHANGELOG 는 자기를 만든 커밋을 담을 수 없어서**,
`HEAD` 를 박으면 내보내고 커밋하는 순간 스스로 「낡음」이 됩니다. 그러면 `--check` 가 영구히
빨간불이 되고, **늘 켜져 있는 경보는 경보가 아닙니다** — 오늘 로컬 점검에서 배운 것을 여기서
반복할 뻔했습니다. 그래서 이 파일만 고친 커밋은 기준에서 뺍니다.

## 3절 — 배포가 한 번 더 돌지 않습니다 (실측)

**Workers Builds 는 커밋이 아니라 push 단위로 돕니다.** 그래서 작업 커밋과 CHANGELOG 커밋을
**같은 push 에 함께** 올리면 배포는 한 번입니다. 세 방안 중 어느 것도 필요 없습니다.

오늘 실측입니다.

```
push 1 → 0f4de0c   빌드 01:35:36Z   배포 01:36:04Z
push 2 → 6f4d9da   빌드 02:04:08Z   배포 02:04:38Z
```

배포가 두 번인 것은 **커밋이 둘이라서가 아니라 push 가 둘이라서**입니다. 이 저장소는
push 가 승인 게이트라 자주 일어나지 않고, CHANGELOG 커밋은 항상 그 push 에 묻어갑니다.

**정정 하나.** 개발 세션이 오늘 낮에 「두 커밋이 한 배포로 합쳐졌다」고 말한 것은 **틀렸습니다.**
배포 목록을 잘라 보다 앞 항목(01:36:04Z)을 놓친 오류입니다. `logs/service_check.csv` 8/21 행에
정정을 적었습니다.

다만 **커밋은 반드시 갈라야 합니다.** CHANGELOG 를 다른 파일과 한 커밋에 담으면 그 변경이
기준 커밋이 되어 파일이 자기보다 항상 한 걸음 뒤처집니다. `minigames/CLAUDE.md` 배포 절에
절차로 못 박았습니다.

`docs/` 를 build watch paths 에서 빼는 안(2절 2번)은 **이 건과 무관하게 여전히 유효**합니다 —
`docs/` 는 Worker 번들에도 정적 자산(`public/`)에도 안 들어가므로 문서만 바꾼 push 는 원래
배포가 필요 없습니다. 다만 별개 사안이라 여기서 함께 처리하지 않았습니다.

## 5절 — Master 결정: 갈래 2 (반영 완료)

`log` · `show` · `rev-list` 해제. `status` · `add` · `commit` · `init` 은 계속 금지.

갈래 3(`--no-optional-locks status`)을 반대하신 근거 —
**「붙이기를 잊으면 사고가 나는 플래그는 두지 않는다」** — 가 기술적 사실보다 나은 판단입니다.
실측상 `--no-optional-locks` 는 잠금 시도를 확실히 막지만, 규칙은 지켜질 때가 아니라
**잊혔을 때 어떻게 되는지**로 평가해야 합니다. `git log` 에는 잊을 플래그가 없습니다.

`reward-minigame-research/CLAUDE.md` 에 실측 근거와 함께 반영했습니다. 못 잰 것도 같이 적었습니다 —
**개발 환경은 로컬 NTFS 라 마운트에서 unlink 가 막히는 조건 자체는 재현하지 못했습니다.**
확인된 것은 「`log` 는 lock 을 만들지 않는다」이고, 만들지 않으면 지우기 실패도 성립하지
않는다는 것은 추론입니다. 그래서 **첫 `git log` 는 Master 화면 앞에서 한 번만 돌리고
`.git/index.lock` 유무를 즉시 확인**하는 절차를 규칙에 함께 넣었습니다.

`프로젝트_지침_초안.md:92,98` 은 **조사 세션 소유라 손대지 않았습니다.** 그 두 줄은 아직
`git status --short` · `git log --oneline -3` 실행과 「git 커밋은 개발 세션 단독」을 적고 있어
현행과 어긋납니다. 조사 세션이 고쳐 주십시오.

## 6절 — 소유권: **「조사 소유」로 통일하는 데 반대합니다**

조사 세션이 이 표를 「참고만」으로 올린 것은 맞는 처리였습니다. 다만 별도 대화에서
**「조사 소유로 통일」이 권고로 올라갔고, 그 권고의 근거가 개발 세션의 오류입니다.**

### 문서를 다시 세어 보면 넷이 아니라 다섯입니다

| # | 문서 | scripts/ 소유 |
| --- | --- | --- |
| 1 | `reward-minigame-research/CLAUDE.md:72` | **개발 세션** |
| 2 | `reward-minigame-research/HANDOFF.md:22` | **공동** |
| 3 | `프로젝트_지침_초안.md:92` | **개발 세션** |
| 4 | **`minigames/CLAUDE.md` 맨 아래** | **개발 세션** — 아래 인용 |
| 5 | 2026-08-21 개발 세션 진술 | 조사 소유 |

4번이 01 요청서에서 빠져 있었습니다. 개발 세션 소유 문서이고, 문장이 명시적입니다.

> 게임을 추가·제거하면 그쪽 `data/deployed_games.csv` 와
> `scripts/sync_deployed_games.py` 의 `FOLDER_TO_NAME`, `CLAUDE.md` 의 종수도 같이 고친다.

**개발 세션이 그 파일을 직접 고치라고 적혀 있습니다.**

### 즉 「조사 소유」의 근거는 5번 하나뿐이고, 그것이 틀렸습니다

5번은 제가 8/21 에 파일을 안 읽고 「research 저장소니까 조사 소유겠지」로 말한 것입니다.
근거가 없었습니다. 그리고 그 오류가 사슬을 만들었습니다.

```
① 개발 세션이 「조사 소유」라고 잘못 말함
② 그래서 개발 세션이 고치기를 거부함
③ 그래서 조사 세션이 대신 고침 (CLAUDE.md:72 기준으로는 월권)
④ 그 사실이 이제 「조사가 소유한다」의 근거로 인용됨
```

**③은 선례가 아니라 ①이 낳은 이상 동작입니다.** 그 위에 규칙을 세우면 오류가 굳습니다.
같은 이유로, 조사 세션이 오늘 고친 `data/deployed_games.csv`(DEP-024 확인일 · DEP-016/017)도
`CLAUDE.md:72` 기준으로는 개발 세션 소유입니다 — **그 수정 내용 자체는 옳고 되돌릴 필요가
없습니다.** 규칙과 실제가 어긋나 있다는 사실만 적어 둡니다.

### 그리고 문서가 정한 소유에는 이유가 있습니다

`CLAUDE.md:72` 는 근거를 함께 적고 있습니다 — **"배포 사실의 원천은 서비스 저장소다."**
`FOLDER_TO_NAME` 은 `minigames/public/games/` 의 폴더 목록을 그대로 비추는 표입니다.
게임이 늘어난 것을 **먼저 아는 쪽이 개발 세션**이고, 그래서 개발 세션이 고치도록 둔 것입니다.

### 권고 — 「개발 소유」로 통일하되, 조사 세션의 오늘 작업 방식을 규칙에 넣습니다

한 가지는 분명합니다. 오늘 조사 세션이 그 파일에 한 작업은 **좋았습니다** — 회귀 확인을
붙였고, 되돌리는 법을 적었고, `research_log.md` 에 남겼습니다. 그걸 막자는 게 아닙니다.

세 갈래 중 Master 께서 정해 주십시오.

| 안 | 내용 | 대가 |
| --- | --- | --- |
| **가** | **개발 소유**로 통일 (문서 4개와 일치). 조사 세션은 요청서로 올린다 | 조사 쪽 도구인데 왕복이 생긴다 |
| **나** | **공동**으로 통일 (`HANDOFF.md:22` 방식). 고치기 전 handoff 에 남긴다 | 오늘 실제로 일어난 방식에 가장 가깝다 |
| **다** | **조사 소유** (원 권고). 대신 `FOLDER_TO_NAME` 갱신 책임을 개발 세션 요청서로 넘긴다 | 문서 4개를 고쳐야 하고, 근거가 된 진술이 오류였다는 점이 남는다 |

**개발 세션 권고는 「나」입니다.** 「가」는 문서 수로는 우세하지만 매일 그 스크립트를 돌리는
쪽이 조사 세션이라 왕복이 실제 비용이 됩니다. 「나」는 오늘의 실제 작업 방식과 같고,
`HANDOFF.md` 에 남기는 절차가 오늘 사고(누가 고쳤는지 모름)를 정확히 막습니다.

어느 쪽이든 **문서 다섯 곳을 한 번에 맞춰야 합니다.** 개발 소유 문서(1·4)는 개발 세션이,
조사 소유 문서(3)는 조사 세션이, 공동 문서(2)는 각자 자기 절을 고칩니다.
