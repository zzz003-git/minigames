# ㉚ 쭉 — 구현 명세

기획서 `../reward-minigame-research/plans/2026-08-01/PLAN-23_쭉.md`
(`IDEA-2026-0023`, 안정형 / 엔진 A 타이밍 — 변형 지속) 를 구현한 문서입니다.

원리 사전 10개 중 **원리 7 「커지는 것」을 정면으로 쓰는 자사 첫 기획**입니다.
그래서 이 문서의 절반이 「어떻게 늘어나고 어떻게 끊어지는가」입니다 — 기획서 16장이
최상위 위험으로 든 것도 그것입니다.

---

## 1. 규격에서 벗어난 항목

| 항목 | 규격 | 이 게임 | 이유 |
|---|---|---|---|
| 조작 | 탭 1종류 | **연속 드래그** | 늘어나는 감각이 기획의 전부입니다(기획서 16장 위험 1). 탭으로 바꾸면 게임이 남지 않습니다 |
| 실패 시점 | 명확한 한 순간 | **실패 없음** | 끊어짐은 종료이지 실패가 아닙니다. 그때까지의 길이가 전액 기록입니다(기획서 6장) |
| 제한 시간 | 있음 | **없음** | 「천천히 끌수록 유리」가 설계의 축입니다(기획서 4장 3번) |

**대체 경로**: 키보드·보조기기는 방향키로 끌고 Enter/Space 로 손을 뗍니다. 한 번 누를
때마다 무대의 2% 만큼 끌리므로 「천천히」가 기본값이 됩니다.

---

## 2. 손상 모형 — 이 게임의 전부

기획서 0절 안티패턴 검사가 「끊어지는 지점은 끄는 속도와 각도의 물리 결과다(숨은 난수
아님)」를 명시합니다. 그래서 아래 식 하나로 전부 결정됩니다.

```
손상률 = (길이/LEN_REF)^ALPHA × (손가락속도/SPEED_REF)^BETA    ← 응력항: 급하면 커집니다
       + FATIGUE × (길이/LEN_REF)^GAMMA                       ← 피로항: 가만히 있어도 쌓입니다

누적 손상이 CAPACITY 에 닿으면 끊어집니다. 단 첫 GRACE_MS 동안은 끊어지지 않습니다.
```

길이의 단위는 **무대의 짧은 변**입니다(1.0 = 화면 하나).

| 상수 | 값 |
|---|---|
| `ALPHA` / `BETA` / `GAMMA` | 1 / **2** / 1 |
| `SPEED_REF` | 1.1 화면/초 |
| `FATIGUE` | 0.04 /초 |
| `CAPACITY` | 0.88 |
| `MAX_STRETCH_RATE` | 0.5 화면/초 |
| `GRACE_MS` | 3000 |

### 왜 두 항인가

`BETA > 1` 이라 **급하면 손해**입니다. 그런데 응력항만 두면 최적 전략이 「무한히 느리게」로
수렴해 게임이 정체됩니다(기획서 16장 위험 3). 피로항이 그것을 막습니다 — 느릴수록 오래
걸리고, 오래 걸릴수록 피로가 쌓입니다.

두 항이 반대 방향이라 **최적 속도가 하나** 생깁니다. 상수 하나로 상한을 거는 것이 아니라
모형 자체가 곡선을 만듭니다.

| 손가락 속도 | 최종 길이 | 걸린 시간 |
|---|---|---|
| 0.05 화면/초 | 1.45 화면 | 28.9초 |
| 0.15 | 2.12 | 14.2초 |
| **0.20~0.22** | **2.20** | **10~11초** |
| 0.30 | 2.15 | 7.2초 |
| 0.50 이상 | 1.50 | 3.0초 (보장이 풀리는 순간) |

기획서 6장의 「한 판 10~20초」와 15장 가설 2(천천히 끄는 이용자가 기록이 높다)가
그대로 나옵니다.

### 늘어나는 속도에 상한을 두는 이유

손가락이 아무리 빨라도 점성 물질은 그만큼 늘어나지 않습니다(`MAX_STRETCH_RATE`).
상한이 없으면 **「첫 3초 보장」이 빠른 사람에게 유리한 장치**가 됩니다 — 3초 동안 마음껏
길이를 벌 수 있기 때문입니다. 상한을 두면 급하게 끈 손가락은 길이는 못 얻고 응력만
얻습니다. 기획서 4장 3번 「급하게 끌면 국부 응력이 커져 빨리 끊어진다」가 그대로입니다.

### 길이에 하드 상한이 없다

기획서 4장 4번이 「길이의 상한이 없다」입니다. 코드에 상한은 없고, 피로항 때문에 이
모형이 실질적으로 인정하는 길이가 약 2.2 화면에서 막힐 뿐입니다. 이어 붙이기로 더 갈 수
있고, 상수를 바꾸면 곡선 전체가 움직입니다.

## 3. 화면과 서버가 같은 식을 갖는다

`public/games/stretch/game.js` 의 `damageRate` 와 `src/games/arcade/stretch.js` 의
`damageRate` 는 **같은 식**입니다. 상수는 서버가 라운드에 실어 보내므로(`round.model`)
화면에 값을 적지 않습니다. ㉑ 퍼펙트 스택의 `blockX` 와 같은 성질의 이중 구현입니다.

다른 점이 하나 있습니다.

```
화면   실제 손가락 속도로 판정합니다 (pointermove 로 재는 값)
서버   표본에서 구한 Δ길이/Δ시각으로 판정합니다 (손가락 속도의 하한)
```

늘어나는 속도에 상한이 있으므로 Δ길이/Δ시각은 실제 손가락 속도보다 **작거나 같습니다.**
하한을 쓰면 손상이 과소평가되어 판정이 늘 사용자에게 유리한 쪽으로 기웁니다 —
화면이 보여 준 길이가 서버에서 깎이는 일이 없습니다.

그런데도 피로항 때문에 서버가 인정하는 길이는 약 2.2 화면에서 막힙니다. 상한 속도로
60초를 당겼다고 신고하면(30 화면) 서버는 그 훨씬 앞에서 끊습니다 — 길이를 부풀린 신고는
거부가 아니라 **끊어졌어야 할 지점에서 잘립니다**(㉘ 톡톡의 경로 자르기와 같은 처리).

### 한 번의 끌기가 여러 조각으로 온다

손을 대고 있는 동안 판이 끝나지 않으므로 잘 끄는 사람은 20초 넘게 이어집니다. 한 번에
보내면 요청이 커지고 상한에서 잘려 화면이 본 길이와 기록이 어긋납니다(㉘ 에서 실제로
겪었습니다). 그래서 표본이 `FLUSH_AT` 개 모이면 조각을 보냅니다(`ongoing: true`).
조각은 판을 끝내지 않습니다.

**길이는 조각을 가로질러 절대값으로 이어집니다.** 다음 조각의 첫 표본은 앞 조각의 마지막
길이이고, 줄어드는 신고는 서버가 거부합니다.

## 4. 그림은 베지어 2개

기획서 16장 위험 2가 「변형 메시는 구형 단말에서 무겁다 → 정식 물리 엔진 대신 베지어
곡선 2개 + 두께 함수로 근사」를 요구합니다. 그대로 구현했습니다.

```
양쪽 윤곽선을 이차 베지어 하나씩, 뿌리와 끝은 반원으로 닫습니다.
두께 h(뿌리) · h(가운데) · h(끝) 세 값만 있으면 넥킹이 나옵니다.
프레임마다 갱신하는 것은 path 의 d 문자열 하나뿐입니다.
```

- **쉬는 덩어리는 원이어야 합니다.** 길이 0 에서 세 두께가 같아지도록 보간합니다
  (`t = min(1, len/0.5)`). 보간을 넣기 전에는 시작 화면의 덩어리가 반원으로 잘려
  보였습니다.
- **반원의 sweep-flag 는 0 입니다.** 1 로 두면 두 반원이 몸통 안쪽으로 돌아 양끝에
  초승달 조각이 삐져나옵니다(브라우저 확인에서 그렇게 보였습니다).
- 손을 대기 전에는 아주 느리게 숨쉬듯 움직입니다(기획서 0-1) — 「말랑한 덩어리는
  잡아당기고 싶어지는 물건이다」를 글 없이 알려 주는 자리입니다.
- 늘어난 만큼 **색이 옅어지고**(`--fade`), 장력이 높을수록 **윤곽이 또렷해지며 떱니다**
  (`--tension`).
- 화면 끝에 닿으면 그리는 길이가 `RENDER_SPAN` 에서 멈추고 **시야가 줄어듭니다**
  (기획서 4장 4번). 0.4 로 두었더니 무대의 3분의 1도 못 채워 0.62 로 올렸습니다.

## 5. 손이 화면에 닿아 있는 동안 끝난다

**끊어지는 순간 손가락은 화면 한복판에 있습니다.** 그래서 두 가지를 겁니다.

- 끊어짐 연출 뒤 **400ms 입력 잠금** (`armScreen`). 버튼 위치를 피해 배치하는 방식으로
  막지 않습니다 — 화면 크기가 바뀌면 깨집니다(기획서 0-H).
- 앱을 잠깐 벗어나면 rAF 가 멈춥니다. 돌아온 첫 프레임의 `dt` 를 **0.1초로 자릅니다.**
  자르지 않으면 그 한 프레임에 손상이 몰려 **가만히 있었는데 툭 끊어집니다.**

`armScreen` 은 `public/shared/run.js` 에 있습니다 — ㉙ 소등과 함께 씁니다.

## 6. 순위 지표

**늘린 길이**뿐입니다(길수록 상위). 걸린 시간으로 동점자를 가르지 않습니다 — 그러면
빨리 끄는 쪽이 유리해져 「천천히 끌수록 유리」가 뒤집히고, 15장의 우선 검증 가설 2를
잴 수 없게 됩니다.

「끊긴 자리에서 이어 붙이기」는 길이와 기록을 그대로 두고 **손상만 0 으로** 되돌립니다.
첫 3초 보장은 **되살리지 않습니다** — 되살리면 이어 붙일 때마다 3초씩 마음껏 당길 수
있어 광고를 본 사람이 실력이 아니라 보장으로 이깁니다. 이어 붙인 판은 엔진이 `'+'`
리그로 따로 집계합니다.

## 7. 광고주 (기획서 10장)

**늘어나는 물체 자체가 광고주 상품입니다.** 「쭉 늘어나는 것」이 상품 특성인 업종이
실재합니다 — 치즈·피자·엿·떡·껌·면류.

- `DOUGHS` — 오늘의 재료. 날짜로만 정해지므로 저장할 상태가 없습니다(㉘ 「오늘의 포장」과
  같은 방식). 브랜드 주간에는 이 배열을 갈아 끼웁니다.
- `PRODUCTS` — 늘리는 도중 덩어리 안에서 드러나는 상품. 어느 길이에서 드러나는지는
  공개입니다(알아도 골라 뽑을 수 없고, 숨기면 화면이 그릴 수 없습니다).
- 부산물: 어느 길이에서 손을 멈추는지의 **위험 회피 성향 데이터**.
